# Root cause

Removing `useSectionInView` from all content components in the previous SSR conversion left
`activeSection` stuck at its initial value ("About"). When the user scrolled down to Skills
manually (without clicking nav), `activeSection` never changed. The SideScroller's
`showArrowUp = activeSection !== data[0].key` evaluated to `false` (since activeSection was
already "About"), hiding the up-arrow and making it impossible to use the side arrow to
navigate back.

Clicking the top-pill "About" link did work (it calls setActiveSection directly), but this was
unintuitive — the UI showed "About" as already active even when viewing Skills.

# Fix

Created `src/components/common/SectionTracker.tsx` — an invisible client component (`<span ref>`)
that attaches a `useInView` intersection observer inside each section. When the section scrolls
into the rootMargin zone (`-40% 0px -50% 0px`), it calls `setActiveSection(sectionKey)`.

Added `<SectionTracker sectionKey="..." />` as the first child of:
- `Intro.tsx` → sectionKey "About"
- `Skills.tsx` → sectionKey "Skills"
- `SoftSkills.tsx` → sectionKey "Skills"
- `Projects/index.tsx` → sectionKey "Projects"
- `Experience/index.tsx` → sectionKey "Experience"

Content sections stay as Server Components. The tracker is the only client boundary.
